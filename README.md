# 트리플스트리트 QR 가이드맵

송도 트리플스트리트 고객이 매장 곳곳의 QR을 휴대폰으로 스캔하면 **현재 위치**가 층별 지도에 표시되고, 가고 싶은 곳을 누르면 **층을 넘나드는 경로**를 선으로 안내하는 모바일 웹 가이드맵입니다.

**▶ 바로 열기: https://hyeonn31.github.io/triple-street-guide-map/**

## 주요 기능

- **QR 스캔 → 현재 위치 표시**: QR마다 고유 주소(`#1f-1` 등)가 있어서, 스캔하면 해당 층 지도가 열리고 현재 위치가 빨간 점으로 표시돼요.
- **층별 지도 4개 탭**: 2026-08-26 가이드맵 PDF에서 층별 도면을 잘라 4개 탭으로 나눴어요.

  | 탭 | 구역 | 비고 |
  |---|---|---|
  | 1F | 송도 가로수길 · 세고비아 8번가 | |
  | 2F | 하바나 2번가 · 송도주가 · 송도놀이터 | |
  | B1–B3 | 나폴리 1번가 · 메이플파크 | A·C동 B2, B동 B3, D동 B1 |
  | 3–6F | 골든파크 · 메가박스 | 5F·6F는 D동 |

- **길 안내**: 매장을 검색하거나 지도의 아무 곳이나 누르면 최단 경로를 계산해서 선으로 그려요. 다른 층이면 엘리베이터나 에스컬레이터 탑승 단계까지 함께 안내해요.
- **매장 검색 · 분류**: 가이드맵 층별 안내의 전체 매장 185곳(여러 층 매장 포함 205개 위치)과 편의시설 34곳을 패션 / 푸드·카페 / 즐길거리 / 생활 / 편의시설(화장실, 안내데스크, ATM)로 나눠 볼 수 있어요.
- **확대 · 이동**: 두 손가락 확대, 드래그 이동, 마우스 휠을 지원해요.
- **다크 모드**: 휴대폰 설정을 따라가요.

## 구조

외부 서버나 빌드 과정 없이 동작해요. 화면과 매장 데이터는 `index.html`, 통로 경로망은 `routes.json`에 있어요. 층별 지도 이미지 4장은 WebP로 HTML 안에 들어 있어요(약 0.4MB).

```
triple-street-guide-map/
├── index.html      # 화면 · 지도 이미지 · QR · 매장 데이터 · 경로 계산
├── routes.json     # 통로 경로망 (관리자 화면에서 편집·저장)
├── README.md
└── docs/           # README용 스크린샷
```

좌표는 모두 **지도 이미지 가로 2000px 기준 픽셀**이에요.

| 위치 | 데이터 | 역할 |
|---|---|---|
| index.html | `PANELS` | 층 탭 4개 (이름, 부제, 이미지 크기) |
| index.html | `QRS` | QR 지점 21곳 (코드, 탭, 좌표, 이름, 설명) |
| index.html | `QR_ALIAS` | 예전 QR 주소 호환표 |
| routes.json | `nodes` | 통로 경로망의 점: `"id": ["탭", x, y]` (탭: `1F` `2F` `B` `U`) |
| routes.json | `edges` | 두 점을 잇는 통로: `["점1", "점2"]`, 추가 비용이 있으면 `["점1", "점2", 200]` |
| routes.json | `lifts` | 엘리베이터 · 에스컬레이터. 엘리베이터는 운행층끼리 바로 연결하고, 에스컬레이터는 `m` 배열 순서대로 **한 층씩만** 연결해요 (아래층 → 위층 순서) |
| routes.json | `costs` | 층간 이동 비용 (`ev` 엘리베이터, `esc` 에스컬레이터 한 층) |
| index.html | `POI` | 검색 · 목적지 239곳 `[이름, 탭, x, y, 분류]` (가이드맵 2페이지 층별 안내 기준) |

**경로 계산 방식**: 출발점과 목적지를 가장 가까운 통로 선에 붙인 다음, 다익스트라(Dijkstra) 최단 경로를 구해요. 통로 비용은 실제 길이 + 추가 비용이고, 층간 이동 비용은 기본 엘리베이터 320, 에스컬레이터 한 층당 240(픽셀 단위 가중치)이에요. 같은 에스컬레이터로 여러 층을 이어 타면 안내에서는 한 단계로 묶어 보여 줘요.

**검증**: QR 21곳 × 목적지 239곳 = 5,019개 경로가 모두 계산되는지 확인했어요 (2026-10-01). `routes.json` 분리 후에도 경로 결과가 같은지 확인했어요 (2026-10-02).

`index.html` 안의 `ROUTES_FALLBACK`은 `routes.json`을 불러오지 못할 때(파일을 직접 열었을 때 등)만 쓰는 예비본이에요.

## 경로 고치는 법

QR 주소는 경로 데이터와 상관없어서, 경로를 아무리 고쳐도 **QR을 다시 인쇄할 필요가 없어요.**

### 처음 한 번: GitHub 토큰 만들기

1. GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. **Repository access**: Only select repositories → `triple-street-guide-map` 하나만 선택
3. **Permissions → Repository permissions → Contents: Read and write** (다른 권한은 필요 없어요)
4. 만료일을 정하고 생성 → 관리자 화면의 **GitHub 토큰** 칸에 붙여 넣기

토큰은 그 브라우저에만 보관되고 GitHub에만 전송돼요. 같이 쓰는 PC라면 "이 기기에 기억하기"를 끄세요.

### 고치기

1. `#admin`으로 열고, **QR 스캔 테스트**로 출발지를, 검색으로 목적지를 정해요. 이제부터 고칠 때마다 경로가 바로 다시 그려져요.
2. **경로 편집 도구 → 편집 켜기**를 누르면 지도 위에 도구가 나타나요.

| 도구 | 하는 일 |
|---|---|
| 선택·이동 | 점을 끌어 옮겨요. 점을 누르면 층간 이동수단 지정, 선을 누르면 **추가 비용**을 줄 수 있어요 |
| 점 추가 | 빈 곳을 누르면 새 점, 선 위를 누르면 선을 나눠 점을 넣어요. 선택한 점과 자동으로 이어져서 연달아 누르면 통로가 그려져요 (선택한 점을 다시 누르면 선택 해제) |
| 연결·끊기 | 두 점을 차례로 누르면 이어지고, 이미 이어져 있으면 끊겨요 |
| 삭제 | 점이나 선을 눌러 지워요 |
| ↶ | 한 단계 되돌리기 |

- 파란 선 = 일반 통로, **주황 점선 = 추가 비용이 있는 통로**, 주황 점 = 엘리베이터·에스컬레이터
- **추가 비용**: 짧아도 실제로는 불편한 길(계단, 혼잡 구간, 문 통과)이면 값을 올려요. 200을 넣으면 200만큼 더 먼 길로 계산해요. 지나가면 안 되는 길은 끊는 게 정확해요.
- **층간 이동 비용**: 값을 올리면 엘리베이터보다 걷는 길을 더 선호해요.

3. **GitHub에 저장**을 누르면 `routes.json`이 커밋되고 1~2분 뒤 모든 고객 화면에 반영돼요.
   - 저장 전 수정본은 그 브라우저에 자동 보관돼요. 창을 닫았다가 다시 열면 **불러오기**로 이어서 작업할 수 있어요.
   - 토큰 없이 저장하려면 **JSON 복사**나 **파일 받기**로 받은 내용을 GitHub의 `routes.json`에 직접 붙여 넣어도 돼요.
   - 다른 곳에서 먼저 저장된 내용이 있으면 덮어쓰기 전에 확인을 물어봐요.

### QR · 매장 고치기

**경로 편집 도구 → 좌표 기록**: 선택·이동 모드에서 빈 곳을 누르면 `['1F', 1234, 456]` 형식의 좌표가 기록돼요. GitHub에서 `index.html` → 연필(✏️) 아이콘을 눌러 고쳐요.
- **QR 추가**: `QRS`에 `{id:'1f-6', p:'1F', x:…, y:…, name:'…', desc:'…'}` 한 줄 추가
- **매장 추가 · 변경**: `POI`에 `['매장명','2F',x,y,'food']` 수정

> 수정이 바로 안 보이면 **Ctrl + Shift + R**(강력 새로고침)이나 시크릿 창으로 확인하세요. GitHub Pages는 최대 10분 정도 캐시를 유지해요.
